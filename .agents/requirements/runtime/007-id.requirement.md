# Incremental id

## Requirement

Preconditions:

- A program evaluates `(id)` in a handler. It does not import `id`.

Expected behavior:

- The text MUST be 32 lowercase hex digits, 16 bytes. Bytes 0–7 are the
  dispatcher clock in milliseconds, bytes 8–11 the increment, and bytes
  12–15 random, each big-endian. The id MUST be globally unique the way an
  ObjectId or a UUID is: the timestamp places it in time, the increment
  separates calls in one millisecond of one runtime, and the random bytes
  separate runtimes.
- A test that starts the dispatcher at 0 (`World::start`) with the initial
  World RNG MUST mint `0000000000000000000000003c88596c` first and
  `0000000000000000000000015e8885db` second. The second MUST sort after the
  first. That start is not a production run.
- An id minted at dispatcher time 1 ms on that same test start MUST be
  `0000000000000001000000003c88596c` and MUST sort after the second id
  from time 0.
- The random bytes MUST be the low 32 bits of one World RNG step. `(id)`
  then `(rand 0 1000000)` MUST equal the second `(rand 0 1000000)` of a
  test run that only calls `rand`. The call MUST NOT change `cryptoRng`
  and MUST NOT read the wall clock.
- A normal runtime (`World::live`, which `kith run` uses) MUST start the
  dispatcher clock at the current wall time, not at 0. The first `(id)`
  timestamp MUST equal that clock, and its increment MUST be 0. Two normal
  runtimes MUST seed World RNG from entropy, so their seeds differ. When
  they mint in the same millisecond, their random bytes MUST differ.
- Snapshot `idCounter` MUST be the decimal next increment, and
  `idTimestamp` MUST be the decimal dispatcher time that increment belongs
  to. After the first id on a test start at 0, those are `1` and `0`.
  Restore MUST continue from them. Omitting either MUST restore it as
  zero, so the next `(id)` at time 0 is the first id. When restored `now`
  differs from `idTimestamp`, the next increment MUST be 0.
- Increment `4294967295` at time 0 on that test start MUST be
  `0000000000000000ffffffff3c88596c`. The next `(id)` at that same time
  MUST fail with a message containing `exhausted` and MUST leave
  `idCounter` at `4294967296`, `idTimestamp` at `0`, and World RNG
  unchanged. The same exhausted counter at dispatcher time 1 ms MUST
  return `0000000000000001000000003c88596c`.
- `(id 1)` MUST fail the expression and MUST leave `idCounter` at zero.
  Starting a component that does not evaluate `(id)` MUST leave
  `idCounter` at zero. On a test start at 0, `idTimestamp` MUST be zero.

Postconditions:

- Tests: `tests/stdlib.rs` (`req:runtime-007`).
